# 安全与隐私基线

BugTrace 处理开发者命令输出、源码差异、测试结果、仓库历史和模型输入。这些数据可能含凭据、个人信息或专有代码。安全边界是 MVP 功能的一部分，不能仅依赖提示词或用户自觉。

## 数据最小化与脱敏

- 采集端上传前脱敏；默认排除 `.env`、密钥/证书、凭据配置和可配置的敏感路径。
- 至少识别口令、访问令牌、邮箱等方案明确列出的敏感内容；匹配规则、覆盖范围和失败策略应可检查。
- 脱敏失败或无法确定的数据默认停止上传并给出本地提示，不得静默发送原文。
- 本地 JSON Lines 缓冲应限制权限、磁盘占用和保留期限；发送成功后按策略清理。缓冲内容同样按敏感数据保护。
- 日志、异常、调试页面和 Agent 运行记录不应复制原始敏感载荷或秘密。确需保存模型运行记录时，仅保存脱敏版本。

## 模型与 Agent

- 仅向模型发送完成任务所需的脱敏证据；模型供应商、区域、保留策略和数据用途在接入前需要确认并记录。
- 模型输出是不可信输入。使用结构化 schema 校验、证据存在性和内容来源校验；不要因输出格式正确就认定事实正确。
- Agent 工具使用最小权限，只提供只读查询。工具调用次数、输入大小、响应大小和执行时间都必须有上限。
- 模型不可用、校验失败或功能关闭时退回模板流程；不得阻断用户查看已有证据或确认普通方案。
- 未经用户确认，Agent 不得执行命令、修改文件、提交代码、选择提交或发布知识方案。

## 仓库导入与 Git

- 支持范围限公开 HTTPS 地址或用户指定的本地路径；私有仓库认证不属于 MVP。
- 仓库内容均为不可信输入。禁用 hooks，不执行仓库脚本、构建文件、测试、子模块初始化或其他仓库代码。
- 只允许必要的 Git 只读操作；避免拼接 shell 命令，使用参数数组调用进程，并校验 URL、路径和目标仓库边界。
- 限制克隆体积、超时、提交数量、文件数、单个文件大小及 diff 上下文；拒绝或安全处理符号链接和仓库目录外路径。
- 仅接受公开 HTTPS，拒绝本地服务/云元数据地址等非预期网络目标；重定向也应重新校验目标，避免 SSRF。
- 清理临时仓库和缓存；UI 清楚显示读取范围及因限制未读取的内容。

## Web 与服务端

- 对所有 API 输入做类型、长度、枚举和路径校验；对 SQL 使用参数化查询；对输出按上下文编码。
- 认证与授权按项目/用户边界实施；每次读取和写入都校验资源归属，不能仅依赖前端隐藏按钮。
- 限制上传、请求体、分页、检索、并发和模型调用；对可重复请求使用幂等键或明确的冲突策略。
- 默认 HTTPS；本地采集器与服务端通信需限制监听地址和授权方式，避免将无认证控制端口暴露到公网。
- 密钥通过本地安全配置或部署平台密钥管理注入；密钥轮换和泄露处置方式在部署方案中补充。

## 安全变更审查

改动采集器、脱敏、仓库导入、Git 子进程、模型调用、鉴权、文件路径或日志时，评审应明确检查：攻击者可控输入是什么、最坏可读/发送/执行什么、资源是否有界、失败是否安全、敏感数据会出现在哪些存储和日志中。
