# 开发与交付约定

## 当前状态

仓库尚无应用源代码、构建文件或 CI 配置。因此本文先定义实施时需要补齐的开发入口，不虚构当前可运行命令。产品范围、技术方向和 7 周里程碑见 [MVP 范围摘要](MVP_SCOPE.md)；本地完整方案为 `Bug排查轨迹重建与经验复用_MVP阶段方案_v2.docx`。

开始编码的首个变更应补齐：

1. 锁定 Java 版本（17 或 21）、模块结构、前端包管理器、MySQL 版本及全文检索实现。
2. 提供从干净检出可复现的构建、格式检查、静态分析和测试命令，并在 README 中记录。
3. 为服务端、采集器和前端分别提供本地启动/配置说明；配置示例不得含有效密钥。
4. 添加 CI，在每个 PR 上执行格式/静态检查和自动化测试；具体门禁在工具链落地后确定。

## 实施约定

- 需求依据：MVP 方案的范围、功能编号 F1–F17、设计决定 D1–D11 和验收标准。超出范围的工作先单独记录，不混入实现。
- PR 描述至少包括：关联需求/功能编号、用户可见行为、数据/API 影响、安全/隐私影响、验证命令及结果。
- 变更尽量保持可独立审查。涉及多个边界时按采集器、服务端规则/编排、前端或数据迁移拆分。
- 架构选择、技术版本、证据结构、事件 schema 或安全策略若会影响后续兼容性，新增 ADR（Architecture Decision Record），记录背景、备选项、决定、后果和日期。
- 迁移、发布和回滚步骤随变更提交；未实现的阶段不能在文档或 UI 中描述为已完成。

## 推荐 PR 自查清单

- [ ] 改动对应 MVP 范围或明确的已批准决策。
- [ ] 输入校验、异常处理、边界条件和失败降级已考虑。
- [ ] 采集/Agent/Git 改动没有绕过只读、脱敏、证据校验或用户确认。
- [ ] 新增配置有安全默认值和示例说明；密钥未加入版本控制。
- [ ] API、事件、数据库或用户流程变化已同步更新文档。
- [ ] 已运行与改动相关的检查；未运行的检查明确列出原因。
