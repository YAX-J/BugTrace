# BugTrace MVP 范围摘要

本文件是仓库内可分发的产品基线，整理自本地完整方案《Bug 排查轨迹重建与经验复用系统 MVP 阶段方案》。完整方案文件目前位于 `docs/Bug排查轨迹重建与经验复用_MVP阶段方案_v2.docx`，由当前工作区提供；此摘要保留团队实施必须遵守的范围和边界。

## 目标

验证最小闭环是否可行：用户开始排查，系统采集事件并在检查点记录，用户结束后生成有证据的总结，经用户确认后进入知识库并可检索。同时验证“从用户选择的 Git 提交生成 Bug 总结”的冷启动入口。

初始验证关注：关键排查步骤能否重建；有效/无效/待验证尝试分类是否接近人工判断；总结是否引用证据且无编造；失败经验是否可检索；采集开销是否可接受；仅提交证据的总结质量与完整轨迹的差距是否可量化。初始阈值是实验目标，MVP 结束时应报告实测值与偏差原因。

## 用户流程

### 排查会话

用户手动开始会话。系统回溯最近 10 分钟事件，优先用最近异常作为起点；没有异常时允许粘贴错误或选择事件。同一项目同一时刻最多一个进行中会话。用户自行排查，系统持续采集并由规则归类；Agent 只在检查点写短记录。用户选择“已解决”或“放弃”结束，二者都会生成总结草稿；用户编辑、确认后入库。

### 提交总结

用户导入公开 HTTPS 仓库或本地仓库，浏览提交并由规则给出“疑似修复”推荐。用户自己选择一个或多个提交，决定逐个总结或合并总结。Agent 仅根据提交信息、diff、代码上下文和测试线索生成草稿；用户编辑确认后入库，条目标注“仅提交证据”和置信等级。

## MVP 范围

- 采集：非交互命令包装、输出/退出码/耗时、文件快照和 diff、Git 与 Surefire 结果、上传前脱敏、本地 JSON Lines 缓冲。
- 会话：手动开始/结束、起点回溯、单会话约束、事件相关性标记、用户可移出事件。
- 规则：错误指纹、验证事件、修复尝试三分类、回退识别；规则逻辑确定、可重复。
- Agent：过程检查点记录与结束总结、提交总结；共用证据校验和失败降级。
- 知识库：方案确认入库、指纹精确匹配和全文检索；不做向量检索或复杂推荐。
- 页面：工作台、会话详情、经验知识库、采集器管理、仓库与提交总结。

暂缓：IDE 插件、被动 shell hook、自动会话归属/合并、多特征评分调参、主动建议、向量检索、私有仓库认证、批量自动挖掘、issue/PR 抓取、项目管理和统计页面。

## 关键行为与验收基线

- 命令包装记录命令、输出、退出码和耗时；颜色码清除，长输出保留头尾与异常块并标记截断；包装器退出码必须等于被包装命令的退出码。
- 文件监听防抖合并；排除 `target`、`.git` 和 IDE 临时文件；快照与 diff 有界。
- Git 与 Surefire 解析应能展示提交及用例级状态。
- 上传前脱敏口令、令牌、邮箱等；默认排除 `.env` 和密钥文件。断网缓存恢复后不丢、不重。
- 错误指纹按异常/错误类别、归一化消息和前三个应用栈帧生成，行号变化不应改变相同错误的指纹。
- 以主指纹和测试状态为锚判断尝试：消失且相关失败测试转通过为有效；仍存在为无效；没有验证或无法判断为待验证。
- Agent 输出为结构化数据，每项结论引用真实证据；校验结构、引用和关键实体。失败重试一次，再退回模板并清楚标记。
- 用户确认前只保存草稿；失败尝试同样保留并可检索。
- 导入仓库只读、禁用 hooks、不执行仓库代码或构建，并限制大小、耗时、提交数和读取范围。

## 架构方向

- 本地采集器：Java 17/21（待选）、JDK `WatchService`、Git CLI、`bugtrace run` 薄包装脚本。
- 服务端：Spring Boot 3、MyBatis-Plus；事件、规则、会话、Agent 编排/校验、仓库导入和检索。
- 存储：MySQL 8；中文全文检索方式待验证。
- 前端：Vue 3、Element Plus；提示可轮询或 SSE。
- 模型 API 与供应商未定，Agent 可全局关闭，关闭后流程退回模板。

以上是方案方向，不是已搭建能力。技术版本、认证边界、模型数据政策和全文检索方案见 [MVP 实施决策清单](DECISIONS.md)。
