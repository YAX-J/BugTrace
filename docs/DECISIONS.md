# MVP 实施决策清单

本文把 MVP 方案中已明确的决定与实施前仍需落定的选择分开，避免把提案误当成已完成的架构决策。新增长期影响架构的选择时，使用 `docs/decisions/` 下的 ADR 记录。

## 已确定的产品与安全决定

这些来自 MVP 阶段方案，在没有正式修订方案前按既定约束执行：

- 两条入口：排查会话总结；用户选择 Git 提交后生成“仅提交证据”总结。
- 人工控制会话起止、提交选择、方案编辑与知识库入库。
- Agent 只在检查点做记录或生成总结；规则代码负责确定性分类。
- Agent 结论引用证据；校验失败重试一次，再降级为模板。无依据内容标注为未验证/推断。
- 仓库只读导入，禁用 hooks，不执行仓库中的代码；私有仓库认证推迟。
- 上传前脱敏，本地 JSON Lines 缓冲；默认排除密钥与 `.env`。
- MVP 知识检索先做指纹精确匹配和全文检索；暂不做向量检索或复杂推荐。
- MVP 页面为工作台、会话详情、经验知识库、采集器管理、仓库与提交总结。

## 建议的首周默认值

以下是便于开工的建议，必须在对应组件落地前写入 ADR/构建配置；一旦形成配置，以实际配置为准。

| 主题 | 建议默认值 | 落地前验证 |
| --- | --- | --- |
| Java | Java 21，设置明确的 toolchain；保留使用 JDK 17 的部署要求时再选 17 | 开发/部署环境及 Spring Boot 3 依赖兼容性 |
| 构建 | Maven；MVP 已以 `mvn test`、Surefire XML 为核心流程 | 选择单 Maven 工程还是 Maven 多模块；统一根目录构建入口 |
| 前端 | Vue 3 + TypeScript；采用一个团队可复现的包管理器并提交 lockfile | 现有项目模板、Node 版本、Element Plus 支持情况 |
| 数据库 | MySQL 8；采用迁移工具管理 schema | 中文全文检索实际效果、索引和数据量；不满足时再决定外置检索方案 |
| 模型接入 | 通过服务端 provider adapter 封装单一模型 API；先只接一个模型 | 数据驻留/保留政策、结构化输出、工具调用和预算；版本固定并可配置关闭 |
| 事件格式 | JSON schema 版本化；事件 ID 作为端到端幂等键 | 采集器离线重放和 schema 演进策略 |
| 本地采集 | 作为独立进程运行；本机服务默认只绑定 loopback | OS 安装/升级方式、进程鉴权和缓冲数据权限 |
| 认证 | 在确定部署形态前暂不假设单用户或匿名；任何非本机访问必须有认证与项目隔离 | MVP 演示环境是纯本机、局域网还是公网；据此决定账号、授权和部署边界 |

## 开工前阻塞项

第 1 周开始持久化或联网实现前，至少确认：

1. 部署边界与身份模型（尤其采集器如何认证、谁能查看项目事件）。
2. 模型服务商、数据保留政策、允许发送的数据类型和关闭模型后的完整降级路径。
3. 事件 JSON schema、脱敏默认规则、缓冲保留期限和用户删除数据的方式。
4. 中文全文检索验证结果及 Maven 演示仓库选择。
5. 版本锁定：JDK、Spring Boot、MySQL、Node、前端包管理器；将版本写入构建工具和 CI，而不是只留在文字中。
